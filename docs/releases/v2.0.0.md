# ahm v2.0.0

`ahm` is now a records CLI for tasks and ADRs. It owns record files, generated
indexes, and workflow state, and it prints state back to you. It no longer
decides how a project should work.

**This release is breaking.** Six commands are gone, two record families are
no longer ahm-managed, four configuration keys are dropped, and task records
can now live in a user-level home store instead of the repository.

Full upgrade instructions live in
[the workflow upgrade guide](https://github.com/travisennis/ahm/blob/master/docs/guides/workflow-upgrades.md).

## Upgrade

Run this once, from the repository root, with the v2 binary:

```bash
ahm init
```

`ahm init` is idempotent. It reconciles the ahm-owned state that v2 still owns
and leaves everything else alone.

Then, before you use v2 for real:

- **Delete every hook, CI step, script, and instruction that calls a removed
  command.** There are no aliases and no replacements.
- **Decide where task records live.** Existing repositories keep them in the
  project. See [the home store](#the-home-store) below.
- **Commit whatever `ahm init` changed** before running other commands.

## Removed commands

Removed in v1 and gone in v2.0.0:

| Command | What it did | Replacement |
| ------- | ----------- | ----------- |
| `ahm context` | Printed repository briefings and managed-work procedures | `ahm prime` for a live briefing; `ahm task show` for one record |
| `ahm agents` | Printed `AGENTS.md` guidance | Your project's `AGENTS.md` |
| `ahm task work` | Handed a task to an external coding-agent CLI | Your own agent workflow |
| `ahm upgrade` | Refreshed ahm-managed files | `ahm init` |
| `ahm task migrate` | Normalized legacy task front matter | None; the format it produced is the current format |
| `ahm adr migrate` | Migrated legacy ADRs to MADR front matter | None; the format it produced is the current format |

Also removed, and removed before they ever shipped in a release:

- `ahm audit`, `ahm onboard`, and `ahm task groom`.
- The `ahm docs` command group.
- The `ahm records` command group (`records migrate`, `records doctor`,
  `records push`, `records pull`, `records sync`).

The `ahm task` and `ahm adr` lifecycles are otherwise unchanged: every
`create`, `list`, `show`, `start`, `accept`, `complete`, `cancel`, `reopen`,
and `comment` command behaves as it did in v1, with the same flags, exit codes,
and output modes.

## Removed record families

`ahm` no longer reads, indexes, or validates two record families:

- **Research notes** under `.ahm/research/`.
- **ExecPlans** under `.ahm/exec-plans/`. Design plans now live in
  `docs/exec-plans/`.

**Nothing is deleted.** Those files stay exactly where they are. The generated
indexes inside them are now stale, and keeping or removing them is your
project's choice.

The `exec_plan` front-matter field on a task record is retired. `ahm` no
longer reads it; existing values survive a round trip untouched, and the field
carries no meaning.

## Removed configuration keys

`ahm init` drops these obsolete ahm-owned keys from `.ahm/config.json` when it
next runs. Unrelated fields, including fields `ahm` does not know about, are
preserved.

- `taskWork`
- `default_work_agent`
- `projectDocs`
- `research`

## The home store

Task records can live in a user-level home store at `~/.ahm/projects/<key>/`
instead of in the repository. ADRs stay committed under `docs/adr/`.

- **New projects default to the home store.** A repository with no
  `.ahm/config.json` gets `tasks_location: home`.
- **Existing repositories keep project-local records** until you opt in:

  ```bash
  ahm --dry-run store migrate --to home
  ahm store migrate --to home
  ```

  The migration refuses to run when `.ahm/tasks/` has uncommitted changes,
  because the move deletes those files. Commit or discard them first.
- `ahm store path` prints the resolved store root, project key, and records
  directory. Set the absolute `AHM_HOME` environment variable to override the
  default `~/.ahm` root.
- Home-mode records are **machine-local**. They are shared across your branches
  and across your clones only when those clones resolve to the same project
  key, which is derived from the canonical `origin` remote URL with a
  symlink-resolved path fallback. The store is not part of the repository and
  `ahm` never stages or commits it.
- `ahm init` seeds the store's `next_id` counter from the records it finds, so
  task IDs are never reused inside a store.

`ahm store migrate --to project` moves the records back.

## Added

- `ahm prime`: a session briefing with live backlog state. A bare `ahm` runs
  `status`, which exits 1 on validation errors; `prime` is the entry point for
  an agent session.
- `ahm store path` and `ahm store migrate`.
- `ahm adr propose`.
- `ahm task create --depends-on`, `ahm task list --priority`, and
  `ahm task list --effort`.

## Fixed

Roughly 190 commits of work since v1.0.0, including atomic writes on Windows,
ownership-safe workflow locks, non-decrementing task IDs, deterministic
dependency-cycle output, round-trip-safe task and ADR front matter, and
rejection of concurrent edits to a groomed task. The generated
[changelog](https://github.com/travisennis/ahm/blob/master/CHANGELOG.md) has
the full list.
