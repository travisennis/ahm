# Remove the documentation workflow context and procedure

## Summary

Remove context docs and the binary-owned general documentation procedure, update prime and embedded workflow references, and preserve safe legacy cleanup behavior.

## Scope

- Remove `docs` from the supported `ahm context` scopes, help, usage errors,
  structured output, and reference metadata.
- Remove `internal/templates/workflow/DOCS.md` and tests dedicated to its
  rendered content.
- Remove documentation-work routing from `ahm prime`.
- Revise the task workflow so documentation may still be recorded as an
  ordinary project deliverable when a task requires it, but agents are sent
  to project-owned guidance rather than a binary-owned docs procedure.
- Update install/upgrade and workflow guidance for the reduced context set.
- Retain metadata-proven cleanup of an obsolete managed `.agents/DOCS.md`
  during upgrade so removing the live procedure does not strand historical
  ahm-owned files. Do not create, overwrite, or adopt project-owned
  documentation.

This task removes general documentation as a workflow route; it does not imply
that behavior-changing implementation work can leave the project's own user
or contributor documentation stale.

## Acceptance Notes

- [x] Supported context scopes are exactly `task`, `plan`, `adr`, and
      `research`; text/JSON/plain output and usage errors agree.
      `internal/ahm/cli.go` (`validScopes`, `Use`, both usage errors) and
      `internal/ahm/context.go` (instruction map, usage error) list the same
      four scopes. Verified against a fresh build: `ahm context docs` exits 2
      with `unknown context scope "docs" (valid: task, adr, research, plan)`,
      unscoped `ahm context` exits 2 and no longer offers `ahm context docs`,
      and `--help` lists four scopes. The `docs` line was text-only in
      `ahm prime`, so JSON and plain output never carried it.
      `TestContextDocsScopeIsRejected` and
      `TestUnscopedContextErrorsWithGuidance` pin both error strings.
- [x] `ahm prime` no longer advertises documentation as managed-work intake.
      Removed the routing line in `internal/ahm/prime.go`;
      `TestPrimePrintsSessionBriefing` now asserts `ahm context docs` is
      absent. Confirmed against a fresh build's Managed Work Intake block.
- [x] No binary-owned documentation procedure or live DOCS template remains.
      `internal/templates/workflow/DOCS.md` deleted along with the five tests
      that asserted its rendered content. A repository-wide search finds no
      live reference to `workflow/DOCS.md`, the `docs` scope, or
      `ahm context docs` outside historical records (completed/cancelled
      tasks, ADRs 011/016, dated sections of the upgrade guide), the new
      CHANGELOG and upgrade-guide entries, and tests asserting absence.
- [x] Task guidance defers project-documentation policy to project-owned
      instructions while allowing explicit documentation deliverables in task
      scope and acceptance evidence. `internal/templates/workflow/TASKS.md`
      step 6 still requires a documentation-impact assessment and an
      Acceptance Notes record, but now states documentation is an ordinary
      project deliverable and routes to "the project's own documentation
      guidance". Pinned at the template level
      (`TestTasksTemplateRoutesToResearch`) and at the CLI level
      (`TestContextTaskRendersResearchRouting`), both of which also assert
      `ahm context docs` is gone.
- [x] Upgrade safely removes historically managed `.agents/DOCS.md` only
      under the existing ownership rules. `obsoleteManagedFiles` in
      `internal/ahm/install.go` is unchanged and still gated on a metadata
      hash match (conflict-reported instead unless `--force`); covered by
      `TestUpgradeRemovesOwnedInstructionTemplatesAndPreservesProjectAgents`.
      Nothing in the change creates, overwrites, or adopts project-owned
      documentation.
- [x] Focused context/template/install tests, `go test ./internal/templates
      ./internal/ahm`, and `just ci` pass. `just ci` is green through
      `fmt-check`, `tidy-check`, `go vet`, `go test -race -cover ./...`
      (`internal/ahm` 86.3%), `golangci-lint` (0 issues), and `govulncheck`.
      `just docs-md-lint` reports 4 errors, all in the untracked,
      pre-existing, user-owned `review.md`, which is not part of this change;
