# Remove the general documentation command and configuration surface

## Summary

Remove ahm docs check, the project-docs validation scope, projectDocs configuration, general-doc finding codes, and their compatibility/documentation surface after managed-record link coverage is preserved.

## Scope

After task 241b preserves link validation for all four structured record
families:

- remove the `ahm docs` command group and `docs check` flags/output path;
- remove `project-docs` from `status`/`doctor --check`, including its
  deprecation alias and warning;
- remove the typed `projectDocs` config schema, defaults, serialization, and
  all runtime behavior derived from it;
- remove discovery and validation for general project docs, including link
  portability, entry-point budgets, generalized/design-doc index coverage,
  and their docs-specific finding codes;
- remove tests and helpers that exist only for those surfaces;
- update CLI references, workflow specification, upgrade guidance, changelog,
  architecture/vision references, and completion checks that name
  `ahm docs check`;
- ensure upgrade removes an obsolete `projectDocs` field from ahm-owned
  configuration while ordinary metadata reads remain tolerant during the
  transition.

Do not remove or weaken the managed-record link validation established by
task 241b. Do not replace the removed functionality with another
general-purpose documentation framework.

## Relevant Files

- `internal/ahm/cli.go`
- `internal/ahm/status.go`

- `internal/ahm/install.go`
- corresponding focused tests

## Acceptance Notes

- [x] `ahm docs` is no longer a registered command and its former invocations
      fail as unknown-command usage errors.
- [x] `project-docs` is no longer an accepted validation scope; `workflow`
      and `links` remain supported and composable.
- [x] No runtime config type, validator, discovery helper, or finding code
      remains for general project documentation.
- [x] Upgrade behavior removes obsolete `projectDocs` configuration without
      discarding unrelated unknown metadata fields.
- [x] Default doctor/status record validation from task 241b remains covered
      and passing.
- [x] CLI compatibility docs and release/upgrade guidance clearly identify
      the intentional breaking removal.
- [x] Focused CLI/config/validation tests, `go test ./internal/ahm`, and
      `just ci` pass.
