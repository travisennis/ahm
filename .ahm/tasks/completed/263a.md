# Document worktree-based feature-branch workflow in CONTRIBUTING.md

## Summary

Milestone 2: document the worktree flow in CONTRIBUTING.md instead of adding a
helper script. Decision: no scripts/new-worktree.sh and no justfile recipe.
Agents manage git worktrees directly (git worktree add -b feat/<slug>
../ahm-<slug> master, then ahm prime in the worktree), linked worktrees share
the main checkout's hooks directory, and cleanup is git worktree remove +
git branch -d after the PR merges. The operating loop already mandates ahm
prime before work, which regenerates branch-scoped indexes.

## Acceptance Notes

- [x] CONTRIBUTING.md documents the worktree create, prime, and cleanup
      commands and the shared-hooks behavior (Worktree Setup subsection under
      Local Setup).
- [x] Following the documented commands creates a working worktree whose
      ahm prime prints its branch (verified in a scratch linked worktree:
      ahm prime --json reports git.branch=feat/<slug> and hooks resolve to
      the main checkout's .git/hooks; sandbox required an in-repo path
      instead of ../ahm-<slug>).
- [x] No new script or justfile recipe was added (the workflow is documented,
      not scripted).
- [x] just ci passes on master (docs-only change; just ci passed locally on
      the feature branch, docs-md-lint — part of just ci — is clean, and CI
      will verify master again at merge).
