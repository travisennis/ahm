# Fix atomic write directory sync and errno checks on Windows

## Problem

GoReleaser ships windows/amd64 and windows/arm64 binaries, but CI runs ubuntu-latest only, and two portability problems mean Windows is likely broken: (1) `fsyncDir` opens the directory O_RDONLY and calls Sync; on Windows FlushFileBuffers on a read-only directory handle fails (ERROR_ACCESS_DENIED), so every `writeFileAtomic` reports an error after the rename already succeeded — every mutating command "fails" while half-working. (2) `errors.Is(err, syscall.ENOTEMPTY)` tolerance checks will not match Windows' ERROR_DIR_NOT_EMPTY, turning tolerated non-empty-dir cases into hard errors.

## Relevant Files

- `internal/ahm/write.go` (fsyncDir)
- `internal/ahm/install.go` (removeObsoleteManagedFiles ENOTEMPTY check)
- `internal/ahm/records_migrate.go` (removeEmptyRecordDirs ENOTEMPTY check)
- `.goreleaser.yaml` (windows targets)
- `.github/workflows/ci.yml` (ubuntu-only matrix)

## Fix Direction

Skip directory fsync on Windows, replace raw `ENOTEMPTY` comparisons with a
cross-platform helper that also matches Windows' directory-not-empty error,
and add a Windows leg to CI while retaining the existing Windows release
targets.

## Decision

Preserve the published Windows compatibility surface. Skipping directory fsync
on Windows is the established portability compromise; swallowing arbitrary
sync errors would hide unrelated failures. CI must exercise the targets that
GoReleaser continues to publish.

## Acceptance Notes

- [x] `writeFileAtomic` succeeds on Windows in CI: `fsyncDir` is a no-op on
  Windows (`fsync_windows.go`; directory handles cannot be synced —
  FlushFileBuffers on a read-only handle fails with ERROR_ACCESS_DENIED), and
  `fsync_windows_test.go` pins the no-op plus a full atomic write. The CI
  matrix now includes `windows-latest`, and `.gitattributes` (`* text=auto
  eol=lf`) keeps checkout line endings from breaking `gofmt` there.
- [x] Non-empty-directory tolerance works on Windows: raw
  `errors.Is(err, syscall.ENOTEMPTY)` replaced by `isDirNotEmpty`, which
  matches `syscall.ERROR_DIR_NOT_EMPTY` (Errno 145, what `os.Remove` returns)
  on Windows and `ENOTEMPTY` on Unix; portable tests in `dir_notempty_test.go`
  produce real non-empty-dir errors on both platforms.
- [x] CI matrix and release targets are consistent: `.github/workflows/ci.yml`
  runs `just ci` on `[ubuntu-latest, windows-latest]` with `fail-fast: false`;
  `.goreleaser.yaml` retains windows/amd64 + windows/arm64 targets (verified by
  `just ci` -> goreleaser snapshot building both).

## Verification

- `just ci` (fmt-check, tidy-check, vet, test-race, lint, vuln, docs-md-lint,
  build, goreleaser check + snapshot) passes; snapshot builds the six
  published targets including windows/amd64 and windows/arm64.
- `GOOS=windows GOARCH=amd64 go build ./...`, `go vet ./...`, and
  `go test -c ./internal/ahm` all compile.
- Focused tests: `TestWriteFileAtomic*`, `TestCleanupStaleTemps*`,
  `TestIsDirNotEmpty*` pass on macOS; the two Unix-permission tests skip on
  Windows with documented reasons.
- Subagent review of the change found no code defects; it surfaced the CRLF
  `fmt-check` risk on windows-latest, fixed with `.gitattributes`.
