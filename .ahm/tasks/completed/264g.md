## Notes

Disposition: 28 tasks cancelled, 7 re-scoped (155, 168, 236, 249, 254, 257,
258), each with a dated `ahm task comment` recording what ADR 022 changed.
Task 236's dependency moved from the cancelled 235 to 264e
(`ahm task dep remove 236 235`, `ahm task dep add 236 264e`). Tracker 263 and
its child 263g were cancelled and the 263 ExecPlan moved to `completed/` by the
workflow reversal inside this ExecPlan, before this pass, so milestone 1 had
nothing left to close there.

Three judgment calls are worth naming.

The milestone lists named 24 ids; the acceptance criteria decided five more.
Tasks 229, 250, and 251 maintain `applyGroomVerdicts`, `createAuditTasks`, and
the shared groom and audit result parsers; task 255 implements the research and
plan lifecycle commands that ADR 019 proposed, and ADR 022 supersedes ADR 019;
task 256 exports records whose payload was research notes and ExecPlans.

Task 256 is the one cancellation that is a product call rather than a
mechanical one. Its justification — durability and migration rollback for the
external-store design — left the boundary with ADR 022. Reopen it if snapshot
and transport of task and ADR records is still wanted.

Tasks 235, 237, and 238 are cancelled as superseded by task 264e, which
rewrites the same prose surfaces and the same `ARCHITECTURE.md` module map
after the code deletion; their pre-ADR-022 reconciliation has no satisfiable
baseline.

Acceptance note 1 is read as "every task cancelled by this pass". The fourteen
cancellations that predate this task (103, 136, 160, 160c, 160d, 210, 212,
239, 240e, 240f, 240g, 240h, 263, 263g) keep the reasons they were cancelled
with; rewriting them to cite ADR 022 would misstate why they closed.

Documentation impact: none. The pass changed workflow records, not code or
project documentation, so no file under `docs/`, `README.md`, `AGENTS.md`, or
`CONTRIBUTING.md` needed an edit. `ahm doctor` and `ahm status` both report a
clean record set.

Review: an independent Codex review of the uncommitted change (read-only
sandbox unavailable in this environment, so it ran against a copy of the tree
in `/tmp`) reported four findings in round 1, all addressed. Task 256's
cancellation reason now says plainly that the backlog-snapshot case survives and
that the record can be reopened with a task-and-ADR-only scope. Task 264e's
first acceptance criterion gained the historical-record and release-notes
exception its own milestone 6 proof already assumed. The ExecPlan's release
milestone and task 264f no longer create a `release/v2.0.0` branch, which the
workflow reversal had removed. Milestone 1's Work paragraph no longer describes
resolving 263 as pending work. The review's only other note was a trailing
blank line at the end of `155.md` and `236.md`, which is the format
`ahm` itself renders (275 of 319 task records end that way), so it is left
as the tool wrote it.

Round 2 verified those fixes and narrowed the 264e exception from "superseded
ADRs" to the decision record, because ADR 022 is accepted and names the removed
surfaces it decides; that is applied.

Round 3 reported a finding of the same class a third time, so patching stopped
and the class is escalated instead. Task 264c's criterion "no file in
`AGENTS.md`, `CONTRIBUTING.md`, or `docs/` instructs a reader to run a removed
command" cannot hold either, because ADR 022 requires the migration note that
tells legacy-layout consumers to run the final v1 release's `ahm upgrade`
first. The class is: the reduction milestones forbid prose that names a removed
surface, while ADR 022 requires prose that names it — historical ADRs, retained
records, the mandatory migration note, and the release notes. The suspected
design flaw is that each documentation milestone wrote its own absolute
prohibition instead of one shared, exception-bearing rule. Recommendation for
the owner: state the rule once in this plan — no live document instructs a
reader to run a removed command, except the migration and release documentation
ADR 022 requires and the historical record — and have 264c, 264e, and 264f
reference it. Until that decision lands, 264c's criterion is the one task in
`ahm task ready` that carries an unsatisfiable criterion, so acceptance note 4
is recorded as met for the reduced tool and open for this prose-criterion
defect, which predates this pass.
