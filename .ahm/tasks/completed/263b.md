# Enable GitHub branch protection on master

## Summary

Milestone 5 (manual, repo settings): enable branch protection on master requiring pull requests, requiring the ci status check to pass, requiring up-to-date branches, and blocking direct pushes. This is the only real enforcement of feature-branch development; in-repo hooks and docs only nudge.

## Settings Changed (2026-08-02)

Enabled branch protection on `master` via the GitHub API
(`PUT /repos/travisennis/ahm/branches/master/protection`) on 2026-08-02:

- Required pull requests before merging, with 0 required approvals and no
  code-owner review requirement (self-merge of a green PR is allowed).
- Required the `ci` status check to pass, with strict (up-to-date) branches.
- Enforced for admins (`enforce_admins: true`), so no actor or rule is
  exempt from the required-PR rule.
- Disabled force pushes and deletions on `master`.
