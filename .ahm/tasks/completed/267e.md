# Add ahm store migrate for task record location

## Summary

Add the opt-in path: `ahm store migrate --to home|project`. Add
`internal/ahm/store_migrate.go`:

    func (a *app) storeMigrate(to taskLocation, force bool) error
    func moveTaskRecords(from workflowPaths, to workflowPaths) (moved []string, err error)

`--to` is required and validated; the direction is never inferred from state.
The command holds the records lock for the whole move.

Move each record with a read, an atomic write into the destination through
`writeOwned`, and then a removal of the source. Never rename: the store and the
project may be on different volumes, and the move must be resumable and
idempotent, so re-running after a crash or an interrupt finishes the job.

Refuse when the destination holds records for a different project key. Refuse
when records under `.ahm/tasks/` have uncommitted changes unless `--force` is
given, because Git history is the only backup after the move; report the
affected paths when refusing.

The command updates `tasks_location`, rewrites the managed `.ahm/.gitignore`
for the new mode (keep `*.tmp`, because `reconcileFile` still atomic-writes
`.ahm/config.json` there; drop the task-index patterns and `.lock/`), keeps the
ADR index under the project root, regenerates indexes on both sides,
initializes the ID counter from the records present, records the move in the
registry as `migrated_from`, and prints the deletions the user must commit.
`ahm` never stages or commits; the user reviews and commits the move.

`--dry-run` previews every source, destination, deletion, and index write
without writing anything and without creating the store.

Add the drift finding from 267c to `status` and `doctor` output if it is not
already covered, so a half-finished move is visible.

## Acceptance

- `ahm --dry-run store migrate --to home` in a scratch repository lists the
  moves and leaves the filesystem and the store untouched.
- A real run moves the records, leaves the deletions visible in
  `git status --short`, and prints them.
- A second run reports no work. A `--to project` run restores the original
  layout.
- Interrupting a run and re-running it completes the move.
- `ahm store migrate --to home` against a destination holding another
  project's records fails with both paths named.
- `ahm store migrate --to home` with uncommitted task changes fails and names
  the paths; `--force` proceeds.
- `just ci` passes.
