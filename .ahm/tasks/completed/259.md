# Add --depends-on flag to ahm task create

## Problem

`ahm task create` accepts `--priority`, `--effort`, `--labels`, `--status`,
`--parent`, `--description`, and `--body-file`, but has no `--depends-on` flag
to set the initial `depends_on` field. When task sequencing matters, the user
must create the task and then run `ahm task dep add <id> <dep>` (or edit the
file by hand). This is a minor but consistent friction.

## Relevant Files

- `internal/ahm/task_create.go` — create handler, which must accept and write
  the new flag.
- `internal/ahm/task.go` — the `Task` struct already carries `DependsOn`.
- `docs/references/cli/task-commands.md` — the `task create` guarantees section,
  which must document the new flag.
- `.ahm/tasks/active/259.md` — this task.

## Fix Direction

Add a `--depends-on` string flag to `ahm task create` that accepts one or more
task IDs (comma-separated). Before writing the new task file, validate that each
referenced ID exists, that adding them would not create a dependency cycle, and
that no dependency is already completed. On valid input, set `depends_on` in the
front matter to the parsed ID list.

## Acceptance Notes

- [x] `ahm task create "..." --depends-on 123,456` creates the new task with
      `depends_on: 123, 456` in its front matter. Verified by
      `TestTaskCreateDependsOn` (IDs are canonicalized and sorted by ID).
- [x] `--depends-on` with a single ID works: `depends_on: 123`. Verified by
      `TestTaskCreateDependsOn` (short form `1` canonicalizes to `001`).
- [x] Missing ID produces a clear error and no file is created. Verified by
      `TestTaskCreateDependsOnRejectsMissing`
      (`dependency task "999": task "999" not found`, exit 2).
- [x] A dependency that would create a cycle produces a clear error. Verified
      by `TestTaskCreateDependsOnRejectsSelfCycle` (self-reference via the ID
      about to be allocated: `task 001 cannot depend on itself`) and
      `TestTaskCreateDependsOnRejectsDanglingCycle` (existing task referencing
      the ID about to be allocated: `would create a cycle`). Resolution runs
      first, so a resolvable or ambiguous pattern wins over the self-cycle
      fallback (`TestTaskCreateDependsOnResolvesBeforeSelfCycleCheck`,
      `TestTaskCreateDependsOnRejectsAmbiguousNotSelfCycle`).
- [x] A dependency on a completed task produces a clear error. Verified by
      `TestTaskCreateDependsOnRejectsCompleted`
      (`task 002 cannot depend on completed task 001`). Cancelled is rejected
      too (`TestTaskCreateDependsOnRejectsCancelled`), consistent with
      `task dep add`.
- [x] `--depends-on` is compatible with `--parent` (a child task can depend on
      other tasks). Verified by `TestTaskCreateDependsOnWithParent`
      (`001a` with `parent: 001` and `depends_on: 002`).
- [x] `--depends-on` works with `--dry-run` (prints what would be written without
      creating). Verified by `TestTaskCreateDependsOnDryRun`: text output
      includes the planned path, id, and depends_on; JSON output includes
      `"depends_on": [...]`; validation still runs and no file is created.
- [x] `--depends-on` is documented in `ahm task create --help` (flag plus
      example) and in the CLI reference
      (`docs/references/cli/task-commands.md`).
