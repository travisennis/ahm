# Escape ADR front matter scalars when rendering ADR records

## Problem

`renderADR` interpolates `status`, `date`, `decision-makers`, `consulted`,
`informed`, and every `Extra` value into front matter raw, while `renderTask`
routes every front-matter value through `renderFrontMatterScalar`. A value that
starts with a YAML block-scalar indicator corrupts the record, and the command
still exits 0:

```
$ ahm adr create "Test decision" --decision-makers "> Alice, Bob"
warning: unsupported block scalar in front matter field "decision-makers"
001                                    # exit 0, file written
$ ahm adr list                         # record silently vanishes
warning: some ADR files could not be parsed and were skipped
$ ahm status
  "code": "adr_malformed", "path": "docs/adr/001-test-decision.md"
```

Two defects compound: the value is not escaped, and the warning is queued
*before* the write happens, so an unparseable record is written and reported as
success. Quoting is also not round-trip safe — a value like `"Alice"` silently
loses its quotes on the next read.

Task 148 fixed newline rejection and task 193 made *task* front matter
round-trip safe; the ADR renderer was not brought along.

## Relevant Files

- `internal/ahm/adrs.go:187` — `renderADR`.
- `internal/ahm/tasks.go` — `renderTask` / `renderFrontMatterScalar`, the
  reference implementation.
- `internal/ahm/adrs_test.go` — ADR render/parse coverage.
- `docs/references/workflow-spec.md` — ADR front matter format.

## Fix Direction

Route every ADR front-matter value through `renderFrontMatterScalar` so ADR and
task rendering share one escaping contract. Separately, make the block-scalar
condition an error that aborts the write and returns a non-zero exit rather than
a queued warning followed by a successful write — a command must not report
success after writing a record it cannot parse back.

Add round-trip coverage: render then parse must return the original value for
quotes, colons, leading indicators, and `#`.

## Acceptance Notes

- [x] `renderADR` uses the same scalar escaping as `renderTask` for all front
      matter fields, including `Extra`.
- [x] `ahm adr create` with a block-scalar-leading value fails with a non-zero

- [x] Round-trip tests cover quotes, colons, `#`, and leading `|`/`>`/`-` for
      each ADR front matter field.
- [x] `ahm adr list` and `ahm status` report no `adr_malformed` finding for any
