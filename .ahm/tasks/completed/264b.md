# Retire research and ExecPlans as record families

## Summary

Remove the two families ahm will no longer manage: research and ExecPlans.
Delete `research_inbox.go` and the ExecPlan/research validators, the
`RESEARCH.md`, `PLANS.md`, and exec-plan index templates, research and
ExecPlan index generation, and prime's `Active ExecPlans` and
`Recent Research` sections. Retire the `exec_plan` task front-matter field
from the schema so existing values survive as preserved unknown fields. Stop
ignoring removed-family indexes in the managed `.ahm/.gitignore`. Existing
`.ahm/research/` and `.ahm/exec-plans/` content stays on disk untouched and
becomes ordinary project files.

## Scope Notes

Two items in the Summary were deliberately deferred, and one consequential
schema decision is recorded here because both the task text and the ExecPlan
named them:

- `internal/templates/workflow/RESEARCH.md` and `PLANS.md` are **not** deleted.
  The ExecPlan's milestone 4 salvages the procedures with
  `ahm context plan > docs/workflow/exec-plans.md` *before* deleting
  `context.go`; deleting `PLANS.md` here would make that step impossible. This
  milestone therefore deletes only the three templates nothing renders any
  more (`research-index.md`, `exec-plans-active-index.md`,
  `exec-plans-completed-index.md`) and leaves the two procedure templates to
  the milestone that removes their only consumer.
- Prose that still names the retired families is left to milestones 4 and 6,
  following the milestone 2 precedent: the `research` and `plan` scopes in
  `ahm context` and `cli.go`, prime's `Managed Work Intake` block,
  `onboard.go`, `internal/templates/workflow/TASKS.md`, `ADR.md`, and `docs/`.
  Help text that claimed ahm manages research notes or regenerates their
  indexes *was* corrected here, because that claim was made false by this
  change. Milestone 6 must also update
  `docs/references/cli/task-file-format.md`, `docs/references/workflow-spec.md`,
  `docs/guides/workflow-upgrades.md`, and `docs/cli.md` for the retired finding
  codes, the retired `research` config key, the task index's dropped `ExecPlan`
  column, and the narrowed `.ahm/.gitignore` pattern.
- The generated task index no longer has an `ExecPlan` column, because the
  column's value came from the retired schema field. This changes a declared
  compatibility surface (generated index contents) in the same release that
  removes the field; `docs/references/workflow-spec.md` records the format and
  milestone 6 updates it. The `.ahm/.gitignore` written by `init` now ignores
  `tasks/index.md` and `tasks/*/index.md` instead of every `index.md`, so the
  retired families' indexes are no longer hidden; `planRecordsGitignore` only
  adds entries, so pruning a legacy `index.md` line from an already-migrated
  repository is milestone 5's idempotent-`init` reconciliation.

Retired metadata state was also relinquished, matching the milestone 2
precedent for `taskWork`/`default_work_agent`: the `research` config block is
consumed on read so the next write drops it, and `retiredGeneratedIndexes`
relinquishes stale `files` hashes for the six retired index paths.
