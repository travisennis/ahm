# Fix exponential dependency tree expansion in task dep tree

## Problem

`ahm task dep tree` re-expands every shared subtree once per distinct path, so
cost is exponential in graph width rather than linear in node count. Both the
text walker and the JSON builder use `seen` as a *path* stack
(`seen[id] = true` ... `delete(seen, id)`) purely for cycle marking; nothing
records that a node has already been expanded.

Measured on a backlog where each task depends on the next two — an ordinary
"this builds on the previous two" shape:

| tasks | output lines            |
| ----- | ----------------------- |
| 15    | 1,596                   |
| 20    | 17,710                  |
| 25    | 196,417                 |
| 40    | did not finish in 2 min  |

40 tasks is Fibonacci(40) ~ 10^8 lines. `--json`/`--plain` is worse:
`buildDepTree` materializes the entire expansion in memory before `emit`, so it
exhausts memory instead of streaming.

## Relevant Files

- `internal/ahm/task_deps.go:231` — `walk` closure in `taskDepTree`.
- `internal/ahm/task_deps.go:253` — `buildDepTree` for JSON/plain output.
- `internal/ahm/task_deps_test.go` — dependency tree coverage.
- `docs/references/cli/task-commands.md` — `task dep tree` output contract.

## Fix Direction

Separate cycle detection from expansion memoization. Keep the path stack for
detecting and marking cycles, and add a visited/memo set so each node expands
once; subsequent references render as a back-reference rather than a full
re-expansion. For the JSON builder, memoize the produced subtree node so the
result stays a DAG-shaped rendering instead of an exponential tree.

Decide and document how a repeated (non-cycle) reference renders in both text
and JSON — that is a user-visible output change and belongs in the CLI
reference.
