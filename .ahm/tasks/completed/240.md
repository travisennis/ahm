# Integrate research and documentation into managed work routing

## Summary

Integrate research and documentation into the same discoverable routing model that already sends task-backed work to ADR and ExecPlan guidance. Research should be the durable evidence route for material uncertainty, while documentation should be a delivery obligation checked before task completion rather than another `.ahm` workflow record.

## Problem

`ahm prime` advertises `ahm context research` and `ahm context docs`, but `ahm context task` only provides explicit triggers for ADRs and ExecPlans. An agent working a normal task therefore receives no equivalent instruction to preserve durable investigation or assess documentation impact unless the user has already classified the work into one of those routes.

The improvement must preserve proportionality: ordinary code reading must not create research-note churn, internal refactors must not require documentation by default, and project documentation must remain separate from agent working records.

## Intended Flow

1. Capture material, durable uncertainty as research when its evidence should survive the current session or inform multiple tasks, an ADR, or an ExecPlan.
2. Use accepted evidence to make any required architectural decision in an ADR.
3. Use an ExecPlan when the existing task-size and uncertainty triggers apply.
4. Implement and verify the task.
5. Assess documentation impact before completion and update durable project docs when the documented triggers apply.

## Child Work

- Define the creation threshold and ADR handoff for durable research.
- Define documentation as a task delivery obligation and clarify when a new document is justified.
- Add the resulting research and documentation triggers to the task lifecycle context.
- Decide whether durable research metadata or lifecycle commands need stronger enforcement after the guidance contract is clear.
