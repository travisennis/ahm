# Keep a single trailing newline when rewriting an ADR

## Summary

`ahm adr supersede` rewrote the replacement ADR through
`upsertADRMoreInformationLine`, which rebuilds the "More Information" section
by trimming its trailing blank lines and re-joining the lines. When that
section was the last one in the file, the file's final newline disappeared, so
the ADR failed `just docs-md-lint` with markdownlint MD047 immediately after a
successful supersession. Found while superseding the nine ADRs that ADR 022
replaces.

Pre-existing, not a regression from the `ahm adr create` newline fix: a binary
built from `master` reproduces it in a scratch repository.

## Acceptance Notes

- [x] `rewriteADR` normalizes rewritten content to end with exactly one
      newline (respecting the file's CRLF style), so every lifecycle rewrite
      keeps the shape `ahm adr create` produces.
- [x] `renderADR` emits no trailing blank line when an ADR body is empty.
- [x] `TestADRSupersedeKeepsSingleTrailingNewline` covers the failing shape,
      and `TestADRSupersedePreservesCRLFBodyNewlines` now asserts a single
      trailing CRLF.
- [x] Reproduced with a `master` binary before the fix, and verified fixed
      after: the replacement ADR ends `).\n`.
- [x] `just ci` passes, including `just docs-md-lint`.
