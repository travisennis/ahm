# Remove general documentation management from ahm

## Summary

Track the decision and implementation work to narrow ahm to research, ExecPlans, ADRs, and tasks; remove general project-documentation ownership while preserving broken-link checks for those structured records.

## Product Direction

Ahm's first-class domain is structured agent work:

- research preserves durable evidence and uncertainty;
- ADRs preserve durable decisions;
- ExecPlans preserve substantial execution intent and progress;
- tasks preserve actionable work, dependencies, and completion evidence.

General project documentation remains project-owned and project-specific. It
may be an output or acceptance obligation of managed work, but it is not an
ahm workflow type and ahm should not prescribe, index, map, or validate the
repository's general documentation surface.

Broken relative links are still a valid integrity check for the four
structured record families. The default `ahm doctor`/`ahm status` link
validation already covers tasks, research, and ExecPlans; the replacement
must add ADR coverage and constrain discovery to ahm's retained domain before
the broader documentation validators are removed.

## Child Work

- 241a records the narrowed product boundary and supersedes ADR 016.
- 241b makes managed-record link validation explicit and adds ADR coverage.
- 241c removes `ahm docs check`, `project-docs`, `projectDocs`, and the
  general-documentation validators.
- 241d removes `ahm context docs` and the binary-owned documentation
  procedure while preserving safe cleanup of historically managed files.

Task 235 remains the final reconciliation pass over this repository's own
product documentation after the child implementation lands.
