# Split workflow paths into project and record roots

## Summary

Record paths must split into two roots before records can move outside the
project. This milestone is a refactor with no user-visible change, and its
acceptance is that nothing changes.

`internal/ahm/workflow_paths.go` becomes the two-root type described in the
Interfaces section of the ExecPlan: a project root for `.ahm/config.json` and
`docs/adr/`, a records root for task records and their indexes, the resolved
`storePaths` when the records live in the store, and the resolved mode. Keep
`workflowPathsFor(root)` working for existing call sites and tests.

Add named accessors (`configPath`, `adrDir`, `adrIndexPath`, `recordsRel`,
`tasksBucketDir`, `taskFile`), `ownedRoots`, and `displayPath`, which renders a
store path as `store:` plus its store-relative path and leaves project paths
repo-relative.

In `internal/ahm/write.go`, add

    func writeOwned(paths workflowPaths, path string, data []byte) error

which refuses a target outside the owned roots and then calls
`writeFileAtomic`. Route every workflow write through it. The safety guardrail
states that `writeFileAtomic` is an atomicity primitive, not a containment
check, so this helper is where containment lives. Point `cleanupStaleTemps` at
the workflow state directories of both roots: a literal scan of every owned
root would walk a whole repository for `*.tmp` files.

In `internal/ahm/lock.go`, take the lock directory from the records root
instead of joining `.ahm/.lock` onto the project root, so that two clones
sharing one store serialize on one lock.

Migrate call sites from string joins on `a.opts.root` to the accessors. Grep
for `a.opts.root` and `toolRecordsDirName` to find them.

## Acceptance

- The full test suite passes unchanged: no assertion about paths, output, or
  on-disk layout changes in this milestone.
- A new test asserts that `writeOwned` refuses a target outside the owned
  roots, and that it accepts a target under each owned root.
- `just ci` passes.
