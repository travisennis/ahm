# Implement ADR 019 research and plan lifecycle commands

## Problem

Tasks and ADRs have command-owned creation, lookup, lifecycle transitions, and
index regeneration. Research notes and ExecPlans do not. `ahm context research`
instructs agents to pick a layout-specific directory, invent a filename, copy a
template by hand, move files between lifecycle buckets, update task references,
and regenerate indexes. Those are the same operations `ahm` already owns for
other record types, and mistakes surface only later as `status` or `doctor`
findings.

ADR 019 decided this and is still `status: proposed`. Task 154 was the design
spike and is Completed; no task implements the decision.

## Why now

Beyond the standing value, this removes agent dependence on record filesystem
paths. Every record read or write that goes through the CLI is one fewer place
where an agent needs to know or reach a path directly, which reduces exposure to
each agent's sandbox configuration. See
`.ahm/research/topics/external-store-workflow-records.md` — if records ever move
outside the repository, this becomes load-bearing, and it is worth doing whether
or not that happens.

## Direction

- ADR 019 is the specification; re-read it before designing, and update its
  status when the work lands.
- Model the surface on the existing task and ADR commands rather than inventing
  new shapes: `internal/ahm/task_commands.go` and `internal/ahm/adr_commands.go`
  show the established argument, flag, and output conventions.
- Record layout must continue to resolve through `workflowPaths`
  (`internal/ahm/workflow_paths.go`), not through hardcoded directories.
- Index regeneration is centralized in `internal/ahm/indexes.go`; reuse it.
- Update `ahm context research` and `ahm context plan` so their guidance
  describes commands rather than manual file placement.

## Acceptance criteria

- Research notes and ExecPlans can be created, inspected, and moved through
  their lifecycle buckets without hand-editing files or directories.
- Task references and generated indexes stay correct across those transitions
  with no manual `ahm index` step.
- `ahm context research` and `ahm context plan` no longer instruct agents to
  place files by hand.
- Both legacy `.agents/` and `.ahm/` layouts work.
- ADR 019 moves out of `proposed`.
- CLI reference docs under `docs/references/cli/` cover the new commands.

## Verification

`just check` plus the verification policy in `CONTRIBUTING.md`. Exercise both
record layouts, and confirm a full create-to-archive lifecycle leaves indexes
and task references consistent.
