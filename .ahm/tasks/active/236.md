# Enforce CLI documentation parity with Cobra

## Summary

The detailed CLI references manually repeat nearly two thousand lines of command names, scopes, flags, aliases, and behavior already defined in Cobra, and they have fallen behind the executable command tree before. This task adds a mechanical parity boundary so future command-surface changes cannot silently leave the documentation behind.

Task 264e first reconciles the human-maintained references to the reduced
records CLI (ADR 022). This task then protects the remaining ahm CLI contract
as repository-specific test infrastructure, not as a general documentation
feature exposed to consumer repositories.

## Evidence

- `internal/ahm/cli.go`, `internal/ahm/task_commands.go`, and `internal/ahm/adr_commands.go` — authoritative Cobra command, alias, and flag registration.
- `docs/references/cli/global-contract.md`, `docs/references/cli/commands.md`, `docs/references/cli/task-commands.md`, and `docs/references/cli/task-file-format.md` — 1,972 lines of manually maintained CLI contract.
- `docs/references/workflow-spec.md:30-56` — already contains nonexistent `--quiet` and `--verbose` flags, omits `--text`, and has an incomplete command inventory.
- ADR 022 fixes the surviving command inventory: `version`, `init`, `prime`,
  `status`, `doctor`, `index`, `task`, and `adr`, with the task and ADR
  subcommands listed in the design document that delivers the reduction.
- Existing tests cover CLI behavior, but searches under `internal/` and `scripts/` found no test that compares current documentation inventories with the registered command tree.

## Fix Direction

After task 264e lands, create a small, deterministic parity mechanism sourced from the Cobra tree. Prefer a focused test or generated inventory for command names, aliases, global flags, and selected command flags over generating all prose. Keep user-authored explanations and examples in Markdown. Put implementation and tests near the existing CLI tests or in a narrowly named repository-contract test; document the update workflow in `CONTRIBUTING.md`. Do not add a consumer-facing docs command, a new runtime dependency, or parsing of arbitrary prose. If reliable parity would require scraping unconstrained English text, STOP and narrow the contract to explicit machine-readable inventory blocks.

## Acceptance Notes

- [ ] A test or generation check derives the supported top-level commands and persistent flags from the actual Cobra command tree.
- [ ] The parity boundary also covers the task and ADR subcommand inventories, including aliases where documented as compatibility surfaces.
- [ ] Deliberately adding a fake documented global flag or removing a registered documented command makes the focused check fail with a useful message.
- [ ] Current prose examples remain human-maintained; no broad documentation generator or new runtime dependency is introduced.
- [ ] `CONTRIBUTING.md` identifies the exact command contributors run after changing CLI wiring.
- [ ] Focused CLI/documentation-contract tests and `go test ./internal/ahm` pass.
- [ ] `ahm doctor`, `just docs-md-lint`, and `just ci` pass, or the handoff
      records exact environmental blockers.
