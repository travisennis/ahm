# Treat task bodies and review feedback as untrusted input in delegated prompts

## Problem

`buildTaskWorkReviewPrompt` interpolates `task.Body` and
`buildFinalizationPrompt` interpolates the review agent's free-text `feedback`
into prompts for CLIs invoked with `--dangerously-skip-permissions`,
`--dangerously-bypass-approvals-and-sandbox`, or `--trust`. Neither value is
delimited, labelled as data, or constrained.

A task record is authored by anyone with repository write access, and the
review feedback is free text produced by an external model. Both therefore act
as arbitrary instructions to a full-permission agent running on the maintainer's
machine — a committed task body is a persistent, reviewable-looking injection
vector into a process that can edit source and run commands.

Task 218 covers the *advisory* delegations (`audit`, `task groom`) and their
permission profiles; task 223 covers process-tree cleanup on timeout. Neither
covers the record-body-to-privileged-agent path in `task work` itself.

## Relevant Files

- `internal/ahm/task_work.go` — `buildTaskWorkPrompt`,
  `buildTaskWorkReviewPrompt`, `buildFinalizationPrompt`.
- `internal/ahm/task_agents.go` — permission flags per agent.
- `docs/adr/006-task-work-agent-delegation.md` — delegation decision.
- `docs/guardrails/external-agent-orchestration.md` — prompt-building contract.

## Fix Direction

Decide the trust model first: `task work` intentionally delegates with write
authority, so the goal is not to remove that authority but to stop repository
content from reading as operator instruction. Options to weigh, not
prescriptions:

- Fence interpolated record content and review feedback in explicit
  data delimiters with a standing instruction that content inside them is data
  to be acted on as a work description, never as instructions to the agent.
- Prefer pointing the agent at the record (`ahm task show <id>`) over
  interpolating the body, so the content arrives through a tool result rather
  than the system-adjacent prompt.
- Bound and sanitize review feedback before it reaches the finalization prompt.

Whatever is chosen should be consistent with the advisory-side wording that task
218 adds, so the project has one story about untrusted repository content.
