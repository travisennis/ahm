# Canonicalize workflow root output on Windows

## Problem

On Windows, when the repository (or `--root`) sits under a directory that
Windows knows by its 8.3 short name — most commonly the user or runner temp
directory, whose `%TEMP%` is set to the short form — `ahm` echoes the short
form in user-visible output:

```text
# ahm status
root: C:\Users\RUNNER~1\AppData\Local\Temp\myrepo
```

```json
// ahm prime --json
"root": "C:\\Users\\RUNNER~1\\AppData\\Local\\Temp\\myrepo"
```

```text
# ahm prime --plain
"root":"C:\\Users\\RUNNER~1\\AppData\\Local\\Temp\\myrepo"
```

The canonical long form is `C:\Users\runneradmin\AppData\Local\Temp\myrepo`.
The same short form leaks into error messages that embed the root path.
`os.Getwd()` returns the current directory exactly as Windows reports it,
preserving the short form when the directory was reached through one, and a
verbatim `--root` is echoed back unchanged.

## Relevant Files

- `internal/ahm/root.go` — `detectManagedRoot`, `detectRootOrCWD` (Getwd-based)
- `internal/ahm/cli.go` — `--root` flag intake
- `internal/ahm/prime.go`, `internal/ahm/status.go` — output that embeds the root
- `internal/ahm/root_test.go`, `internal/ahm/prime_test.go` — already
  canonicalize expectations via `filepath.EvalSymlinks` (added in task 226
  follow-up); they pin the long form
- `docs/references/cli/` — check whether any page shows sample root output

## Fix Direction

Canonicalize the root once, at the boundary, before it reaches any output:

- In `detectManagedRoot`/`detectRootOrCWD`, canonicalize the returned root with
  `filepath.EvalSymlinks`; on Windows this resolves 8.3 short names to long
  names (`GetFinalPathNameByHandle`). On failure, fall back to the raw path
  (EvalSymlinks is best-effort; never turn root detection into an error).
- Decide scope: canonicalize **only on Windows** (`runtime.GOOS == "windows"`
  or a build-tagged helper) so Unix behavior is unchanged — on macOS
  `EvalSymlinks` would also resolve symlinks (e.g. `/var` → `/private/var`),
  which is a behavior change no one asked for. Windows-only keeps the diff
  minimal and the compatibility surface intact elsewhere.
- `--root` intake: canonicalize the provided path the same way so
  `ahm --root C:\Users\RUNNER~1\... status` reports the long form.

## Decision

Canonicalize the emitted root only on Windows, at the detection and `--root`
intake boundaries, with a graceful fallback to the raw path on
`EvalSymlinks` failure. Unix output is unchanged. This is cosmetic polish:
both forms are valid paths to the same directory.

- [ ] `EvalSymlinks` failure falls back to the raw path without erroring
- [ ] Unix output is unchanged: existing tests still pass and macOS `/var`
