# Add --depends-on flag to ahm task create

## Problem

`ahm task create` accepts `--priority`, `--effort`, `--labels`, `--status`,
`--parent`, `--description`, and `--body-file`, but has no `--depends-on` flag
to set the initial `depends_on` field. When task sequencing matters, the user
must create the task and then run `ahm task dep add <id> <dep>` (or edit the
file by hand). This is a minor but consistent friction.

## Relevant Files

- `internal/ahm/task_create.go` — create handler, which must accept and write
  the new flag.
- `internal/ahm/task.go` — the `Task` struct already carries `DependsOn`.
- `docs/references/cli/task-commands.md` — the `task create` guarantees section,
  which must document the new flag.
- `.ahm/tasks/active/259.md` — this task.

## Fix Direction

Add a `--depends-on` string flag to `ahm task create` that accepts one or more
task IDs (comma-separated). Before writing the new task file, validate that each
referenced ID exists, that adding them would not create a dependency cycle, and
that no dependency is already completed. On valid input, set `depends_on` in the
front matter to the parsed ID list.

## Acceptance Notes

- [ ] `ahm task create "..." --depends-on 123,456` creates the new task with
      `depends_on: 123, 456` in its front matter.
- [ ] `--depends-on` with a single ID works: `depends_on: 123`.
- [ ] Missing ID produces a clear error and no file is created.
- [ ] A dependency that would create a cycle produces a clear error.
- [ ] A dependency on a completed task produces a clear error.
- [ ] `--depends-on` is compatible with `--parent` (a child task can depend on
      other tasks).
- [ ] `--depends-on` works with `--dry-run` (prints what would be written without
      creating).
- [ ] `--depends-on` is documented in `ahm task create --help` and in the CLI
      reference (`docs/references/cli/task-commands.md`).
