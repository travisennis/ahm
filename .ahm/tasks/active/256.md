# Add ahm store export and import for workflow records

## Problem

There is no way to move a backlog between machines, hand it to someone else, or
take a point-in-time backup of workflow state independent of the project's Git
history. Records are durable today only because they are committed, which means
durability is coupled to the storage layout rather than being a capability the
tool provides.

## Why now

This is useful against the current committed layout: a snapshot of task,
research, and ExecPlan state that survives independently of branch history is
worth having on its own.

It is also the prerequisite that makes the external-store design in
`.ahm/research/topics/external-store-workflow-records.md` viable — that design
gives up Git-provided durability and needs an explicit manual replacement — and
the natural mechanism for its migration rollback. Building it first means the
capability is proven before anything depends on it.

## Direction

- Explicit, manual, offline. No daemon, no background reconcile, no network, no
  remote configuration. This boundary is the whole point: ADR 015 rejected the
  previous design for making `ahm` a synchronization engine, and this must not
  become one.
- Export covers source records — tasks, research notes and their attachments,
  and ExecPlans — and excludes generated indexes, which are regenerated by
  `ahm prime` and `ahm index`.
- Records resolve through `workflowPaths` (`internal/ahm/workflow_paths.go`) so
  both supported layouts work.
- Writes go through the atomic path in `internal/ahm/write.go` and take the
  record lock (`internal/ahm/lock.go`).
- Honor `--dry-run` for import, per the global contract in
  `docs/references/cli/global-contract.md`.

## Decisions to make

- **Archive format.** A tarball is simplest and handles attachments; a directory
  copy is easier to inspect. Pick one and state why.
- **Import collision policy.** Refuse on any collision, merge non-overlapping
  records, or write both sides for manual resolution. Refusing is the smallest
  correct starting point and can be relaxed later; silently overwriting a
  backlog is not acceptable.
- **Whether export records provenance** (source repository, timestamp, `ahm`
  version) so an import can warn about format drift.

## Acceptance criteria

- `ahm store export` produces a single artifact containing all source records,
  including research attachments and non-Markdown files.
- `ahm store import` reconstitutes those records into a repository with no
  workflow records, and the first `ahm prime` afterward reports the same backlog
  the source reported.
- Import into a repository with existing records applies the chosen collision
  policy and never silently discards a record.
- `--dry-run` import reports what would change and writes nothing.
- Neither command performs any Git or network operation.
- Both record layouts are supported.

## Verification

`just check` plus `CONTRIBUTING.md` policy. Include a round-trip test:
export, import into an empty repository, and assert the resulting task set,
statuses, dependencies, and attachments match the source.
