# Default new projects to the home store

## Summary

Turn on the new default. `install()` in `internal/ahm/install.go` writes
`tasks_location: home` when it creates configuration for a repository that has
none, and preserves an existing value otherwise. A repository that already has
`.ahm/config.json` without the key stays in `project` mode, which is what makes
this work safe to land in the existing tree.

Root detection is unchanged. A directory holding `.git` or `.ahm/config.json`
is a managed root; a directory with neither still needs `ahm init`, which then
writes configuration with `home` as the mode and, because there is no remote,
keys the project by its symlink-resolved path.

Update `ahm init`'s help text and the CLI reference to say what the command now
creates and where records will live, and note that `--tasks-project` is not a
flag: a person who wants records in the project in a new repository runs
`ahm store migrate --to project` after `ahm init`.

## Acceptance

- `git init` plus `ahm init` in a fresh directory creates configuration with
  `tasks_location: home` and puts a created task in the store.
- A repository whose configuration predates this change keeps its records in
  the project and creates no store entry.
- `ahm init` on a `home` repository never creates `.ahm/tasks/`, including
  when run twice and when run with `--force`.
- A non-Git directory that has run `ahm init` works, keyed by its path.
- `just ci` passes.
