# Reduce ahm to a tasks-and-ADRs records CLI

## Summary

Tracker for implementing ADR 022: ahm becomes a records CLI for tasks and ADRs
with no prescribed workflow. Research and ExecPlans stop being record
families; `context`, `onboard`, `audit`, `task groom`, `task work`, and
`upgrade` are removed; `init` becomes idempotent; docs and instructions are
rewritten to the two-family boundary; the release is v2.0.0.

ADR 022 is the decision of record. This tracker and 264a-264g sequence the
delivery; each child is independently verifiable and lands as its own commit on
`master`, because each one leaves the tree green. This repository does not use
pull requests.

## Ordering

264g (backlog disposal) and 264d (install collapse) are independent of the
rest and may be done at any time. 264a, 264b, and 264c remove code and must
land before 264e rewrites the documentation, because the docs describe the
removed surfaces. 264f is the release and comes last. Recommended sequence:
264g, 264a, 264b, 264c, 264d, 264e, 264f.

## Milestones

- 264a — Delete `task work`, `audit`, and `task groom` with their shared
  delegation plumbing. They share `task_agents.go`, `task_session.go`, and
  `task_parsers.go`, so they can only be removed together.
- 264b — Retire research and ExecPlans as record families: validators,
  index generation, templates, prime sections, and the `.ahm/.gitignore`
  entries. Existing records stay on disk as project files.
- 264c — Remove the procedure channel and the last prescription: `context`,
  `onboard`, prime's routing prose, and status's onboarding snippet. Surviving
  procedure moves into project-owned instructions.
- 264d — Collapse install and upgrade into one idempotent `ahm init`; drop the
  `upgrade` command, the records/task/ADR migrations, and legacy
  `.agents/ahm.json` layout support.
- 264e — Rewrite `docs/VISION.md`, `README.md`, `docs/`, `AGENTS.md`, and
  `CONTRIBUTING.md` to the two-family records boundary; update
  `ARCHITECTURE.md`'s surfaces and module map.
- 264f — Cut v2.0.0 with release notes that name every removed command and
  the required `ahm init` step.
- 264g — Dispose of the queued work that only existed for removed surfaces,
  and close tracker 263.

## Verification

Every milestone ends with `just ci` green and `ahm doctor` reporting no new
findings. The tree after 264a-264d should have no code path that reads
`.ahm/research/` or `.ahm/exec-plans/`, no reference to an external agent CLI,
and no command whose purpose is to tell a project how to work.
