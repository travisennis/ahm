# Add a user-level home store for task records

## Summary

Tracker for implementing ADR 023: task records move out of the project and into
a user-level home store at `~/.ahm/projects/<key>/tasks/`, keyed by the
canonical `origin` remote URL with a symlink-resolved path fallback. ADRs stay
committed under `docs/adr/`. Existing repositories are unaffected until they
opt in with `ahm store migrate --to home`; a repository with no
`.ahm/config.json` is a new project and defaults to the home store.

ADR 023 is the decision of record and the delivery sequence lives in
`docs/exec-plans/active/267-home-store-for-task-records.md`. Read both before
starting. This tracker and 267a-267h sequence the delivery; each child is
independently verifiable and lands as its own commit on `master`. This
repository does not use pull requests.

This work must land before 264f, which cuts v2.0.0.

## Ordering

The children are a chain: 267a, 267b, 267c, 267d, 267e, 267f, 267g, 267h.
Earlier milestones add the seam the later ones build on, and the default
storage mode stays `project` until 267f, so the tree is green after every
milestone. 267g migrates this repository itself, which is the first real use,
and 267h consolidates documentation and hands the release-note items to 264f.

## Milestones

- 267a — Derive project identity and resolve the store root; add the
  `ahm store path` command so the resolver is observable.
- 267b — Split workflow paths into a project root and a records root, contain
  every write to an owned root, and move the lock and temp cleanup with the
  records. No user-visible change.
- 267c — Read and write task records in the store, split index generation,
  report the store from `prime` and `status`, and report drift when records
  stay in the project.
- 267d — Persist a non-decrementing task ID counter in the store.
- 267e — Add `ahm store migrate --to home|project` with resumable moves,
  refusal conditions, and the `tasks_location` write.
- 267f — Default new projects to the home store.
- 267g — Migrate this repository's own tasks to the store.
- 267h — Update the workflow spec, upgrade guide, CLI reference, glossary,
  architecture map, and agent instructions.

## Verification

Every milestone ends with `just ci` green and `ahm doctor` reporting no new
findings. Tests that exercise the store must set `AHM_HOME` to a temporary
directory, because the store otherwise resolves to the developer's home
directory. The milestone in `Plan of Work` that corresponds to each child
states its own acceptance.
