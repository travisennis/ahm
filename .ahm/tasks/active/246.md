# Decide the credential env deny-list for all task work agents

## Problem

`blockedEnvVars: []string{"ANTHROPIC_API_KEY"}` is declared on the `claude`
agent and on nothing else. `codex`, `cursor`, and `cake` inherit the parent
environment unfiltered, including `ANTHROPIC_API_KEY` and every other provider
credential present in the shell.

Task 215 introduced the mechanism for a specific reason — Claude Code in
non-interactive mode prefers `ANTHROPIC_API_KEY` over the active subscription,
which broke billing — and deliberately left other agents unfiltered. But if the
intent is also "do not leak one provider's key into another provider's
subprocess", the current filter is backwards: it strips Anthropic's key from
Anthropic's own tool and leaks it to the other three.

Those are two different goals with different correct answers, and the code does
not record which one is intended.

## Relevant Files

- `internal/ahm/task_agents.go:208` — `blockedEnvVars` on the `claude` agent.
- `internal/ahm/task_work.go` — `runTaskWorkCommand` environment filtering.
- `internal/ahm/task_groom.go`, `internal/ahm/audit.go` — advisory delegations
  that spawn the same agents.
- `docs/guardrails/external-agent-orchestration.md` — orchestration contract.

## Decision Needed

Choose between:

1. **Per-agent billing workaround only** (status quo): the mechanism exists to
   fix Claude Code's non-interactive billing precedence. Document that
   credential isolation between providers is explicitly not a goal, and record
   why.
2. **Shared credential deny-list**: maintain one deny-list of provider
   credential variables applied to every agent, with each agent re-allowing the
   variables it legitimately needs. This isolates providers from each other but
   requires knowing which variable each agent authenticates with, and risks
   breaking authentication for agents that rely on an inherited key.

Option 2 changes agent invocation behavior for every provider and needs live
smoke evidence per `docs/guides/testing.md` before it can ship.

## Acceptance Notes

- [ ] The chosen option is recorded with its rationale, in an ADR if the
      credential-isolation boundary is adopted as a durable decision.
- [ ] If a shared deny-list is adopted, it applies to `task work`, `task groom`,
      and `audit` invocations alike, and each agent's required credentials are
      enumerated.
- [ ] Tests assert the filtered environment for every supported agent in both
      the mutating and advisory paths.
- [ ] Live smoke evidence is recorded for every installed affected provider if
      invocation environments change.
- [ ] `docs/guardrails/external-agent-orchestration.md` states the resulting
      contract.
