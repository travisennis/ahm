# Document worktree-based feature-branch workflow in CONTRIBUTING.md

## Summary

Milestone 2: document the worktree flow in CONTRIBUTING.md instead of adding a
helper script. Decision: no scripts/new-worktree.sh and no justfile recipe.
Agents manage git worktrees directly (git worktree add -b feat/<slug>
../ahm-<slug> master, then ahm prime in the worktree), linked worktrees share
the main checkout's hooks directory, and cleanup is git worktree remove +
git branch -d after the PR merges. The operating loop already mandates ahm
prime before work, which regenerates branch-scoped indexes.

## Acceptance Notes

- [ ] CONTRIBUTING.md documents the worktree create, prime, and cleanup
      commands and the shared-hooks behavior.
- [ ] Following the documented commands creates a working worktree whose
      ahm prime prints its branch.
- [ ] No new script or justfile recipe was added (the workflow is documented,
      not scripted).
