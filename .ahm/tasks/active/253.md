# Remove dead generality in task status and list helpers

## Problem

Three small pieces of unused generality in the task command layer:

- `taskStatusArgs.ids` is a `[]string`, but only `ids[0]` is ever read
  (`task_status.go:45`, `:60`). Every caller reaching it is gated by
  `exactArgs(1)`. As written, the field promises multi-id support that does not
  exist, and an unguarded caller panics on an empty slice rather than failing
  cleanly.
- `a.taskStatus` (`task_status.go:36`) is a thin wrapper with no non-test
  callers; production code goes through `taskStatusWithArgs`.
- `a.taskList` (`task_list.go:12`) likewise has no non-test callers.

Both wrappers are kept alive only by their tests, which means the tests are
exercising a signature production no longer uses.

## Relevant Files

- `internal/ahm/task_status.go:12` — `taskStatusArgs`.
- `internal/ahm/task_status.go:36` — `a.taskStatus`.
- `internal/ahm/task_list.go:12` — `a.taskList`.
- `internal/ahm/task_commands.go:327` — the real `taskStatusWithArgs` caller.
- `internal/ahm/task_commands_test.go` — the tests pinning both wrappers.

## Fix Direction

Make `taskStatusArgs.ids` a scalar `id string` so the type states what the code
actually supports. Delete the two dead wrappers and point their tests at the
functions production uses.

Task 232 removed a previous round of dead wrappers and duplicated helpers in
this package; this is the same cleanup on the surfaces it did not reach.
