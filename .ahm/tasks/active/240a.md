# Define durable research routing and ADR handoff

## Summary

Revise the embedded research workflow reference so agents can decide when investigation deserves a durable `.ahm/research/` record and understand how research evidence feeds tasks, ADRs, and ExecPlans.

## Problem

`ahm context research` explains storage categories and note handling after work has already been classified as research, but it does not provide a sharp boundary between durable investigation and ordinary task-local code reading. Its promotion flow mentions tasks and ExecPlans but omits ADRs, even though research commonly supplies the evidence, options, and constraints behind an architectural decision.

## Fix Direction

Update `internal/templates/workflow/RESEARCH.md` to:

- create durable research when material factual or technical investigation should survive the current session, inform more than one work item, or support an ADR or ExecPlan;
- keep brief, task-specific code reading and implementation observations in the task or ExecPlan rather than creating note churn;
- state that research is evidence, not an authoritative decision or implementation contract;
- include ADRs in the promotion and authority flow, while preserving tasks for actionable work and ExecPlans for broad or implementation-heavy findings;
- preserve the existing inbox, investigation, source, topic, archive, and stale-note disposition model.

Do not introduce new metadata validation, file-format requirements, or research lifecycle commands in this task. Those require a separate compatibility decision.
