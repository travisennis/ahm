# Reuse parsed records across index generation and post-mutation validation

## Problem

Every record mutation reads the same files twice. `writeIndexesForTasks` calls
`indexWritesForPaths`, which reads every research note, ExecPlan, and ADR to
build the indexes. Then `emitPostMutationFindings` calls
`validateWorkflowStateForPaths`, which re-reads all ExecPlans
(`validateExecPlans`), all ADRs (`validateADRs`), and all generated index files
(`validateGeneratedIndexWrites`) — the last of which was just written by the
step before.

So a one-task status change pays two full passes over the record tree. The cost
scales with backlog size, and this repository's own backlog is already the
largest test case.

The pattern is recognized in the code — `validationReport.execPlanSectionsCache`
exists for exactly this reason (task 104), as does the parsed-state reuse from
task 202 — but neither extends across the generate/validate boundary.

## Relevant Files

- `internal/ahm/indexes.go` — `writeIndexesForTasks`, `indexWritesForPaths`.
- `internal/ahm/validation.go` — `validateWorkflowStateForPaths`,
  `validateExecPlans`, `validateADRs`, `validateGeneratedIndexWrites`,
  `execPlanSectionsCache`.
- `internal/ahm/write.go` — `emitPostMutationFindings`.

## Fix Direction

Extend the existing parsed-state reuse so records read during index generation
are handed to post-mutation validation rather than re-read. The generated index
content is the strongest case: validation is checking freshness against bytes
the same command just produced and already holds in memory.

Keep the read-fresh path intact for commands that validate *without* having
generated anything (`status`, `doctor`) — the reuse must be an explicit handoff
from a generation step, not a process-lifetime cache, or validation stops being
able to detect on-disk drift.

## Acceptance Notes

- [ ] A mutation command reads each ExecPlan, ADR, and generated index file at
      most once; a test asserts the read count.
- [ ] `ahm status` and `ahm doctor` still read from disk and still detect
      out-of-band edits and stale indexes.
- [ ] Findings codes and their contents are unchanged — the findings contract is
      a compatibility surface.
- [ ] `just ci` passes.
