# Route task work into research and documentation contexts

## Summary

Make `ahm context task` the discoverable dispatcher for research and documentation in the same way it already routes task-backed work to ADR and ExecPlan guidance.

## Problem

Agents are instructed by `ahm prime` to load `ahm context task` before task work. That task reference currently contains explicit ADR and ExecPlan triggers, but it never tells the agent when ordinary task work should load `ahm context research` or `ahm context docs`. The detailed research and documentation references therefore cannot solve their own discoverability problem.

## Fix Direction

After tasks 240a and 240b establish the detailed route contracts, update `internal/templates/workflow/TASKS.md` with concise dispatch rules rather than duplicating the full references:

- During triage or planning, run `ahm context research` when resolving material uncertainty requires evidence that should survive the session or inform multiple artifacts. Keep brief task-local code reading in the task.
- Leave a task `Open` while material research questions prevent clear scope or acceptance.
- Preserve the existing ADR and ExecPlan triggers, with the conceptual order research evidence, architectural decision, then execution planning when all apply.
- Before task completion, assess documentation impact. Run `ahm context docs` when durable user or contributor knowledge may have changed, then record the documents checked and updated or why no update was needed in Acceptance Notes.
- Do not require research records or documentation changes for every task.

This task changes instructional routing only. Do not add lifecycle commands, automatically create artifacts, or make task completion parse documentation prose.

- [ ] Research is routed during triage or planning, before decisions and execution planning when applicable.
- [ ] Documentation impact is checked after implementation and verification but before task completion.
- [ ] Acceptance Notes must record the documentation disposition without forcing a documentation edit when none is warranted.
