# Constrain link validation to managed records and ADRs

## Summary

Make the default `links` validation scope check exactly ahm's retained
structured record surface: tasks, research, ExecPlans, and ADRs.

## Current Behavior

`ahm doctor` and `ahm status` already emit `markdown_link_missing` for broken
relative links discovered under the workflow record directory. This covers
tasks, research, and ExecPlans in the current `.ahm/` layout, but ADRs under
`docs/adr/` rely on the separate general project-doc scan. The current helper
also walks the broad legacy `.agents/` tree rather than enumerating only the
legacy record roots.

## Fix Direction

- Discover task, research, and ExecPlan Markdown from their resolved current
  or legacy record roots.
- Include ADR source records and the generated ADR index under `docs/adr/`.
- Include the generated indexes belonging to the retained record families
  when they are part of the existing managed-link contract.
- Do not scan README, CONTRIBUTING, ARCHITECTURE, general `docs/`, AGENTS.md,
  CLAUDE.md, skills, or other project-authored Markdown.
- Preserve the existing `links` scope, default doctor/status behavior,
  `markdown_link_missing`/`markdown_link_check_failed` finding codes, output
  modes, and read-only semantics.
- Keep current and legacy record-layout compatibility without treating all of
  `.agents/` as managed documentation.
