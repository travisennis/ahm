# Migrate this repository's tasks to the home store

## Summary

Use it for real. Run `ahm store migrate --to home` in this repository and
verify the whole surface against the store: `ahm prime`, `ahm doctor`,
`ahm status`, `ahm task list`, `ahm task show`, `ahm task next`, and
`ahm index`. This repository has hundreds of task records and its records link
into `docs/` and `docs/adr/`, so it exercises the link-resolution rule and the
generated indexes at scale.

Before migrating, record the current `ahm status` finding set and record
counts. After migrating, confirm that `ahm doctor` reports no new findings,
that the counts match, and that `git status --short` shows only the intended
deletions under `.ahm/tasks/` plus the changed configuration and gitignore.

This milestone is also the shakedown for the upgrade guide: the exact steps
that worked, and any friction, belong in `docs/guides/workflow-upgrades.md`.
Anything that cannot be explained in a short procedure becomes a fix here or a
new task.

Do not migrate while the acceptance notes of an in-progress task are being
edited, and do not commit the move in the same commit as unrelated work.

## Acceptance

- This repository's backlog is served from the store; `ahm prime`,
  `ahm status`, and `ahm task list` read it, and no task file remains under
  `.ahm/tasks/`.
- `ahm doctor` reports no findings.
- `git status --short` shows only the migration's intended changes, and the
  deletions are reported in the handoff for a commit the user makes.
- The ExecPlan records the observed friction and the guide's final steps.
