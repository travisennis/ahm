# Persist a non-decrementing task ID counter in the store

## Summary

`nextTaskID` in `internal/ahm/task_create.go` derives the next ID from the
highest parsed task ID plus the filesystem entries. In Git, deleting the
highest-numbered task file is safe because history proves the ID was used. In
the store there is no history, so the same code reissues the ID.

Persist the counter in the records root's `project.json` as `next_id`, at the
path `storePaths.statePath()` from the ExecPlan. `nextTaskID` reads the
persisted value and takes the maximum of it and the highest record present, so
an existing store self-heals upward; it then persists the incremented value as
part of the same locked read-compute-write sequence the command already holds.
Never decrease the value. Child allocation under `--parent` keeps its current
26-child limit and scan, against the same counter.

`ahm init` and `ahm store migrate` must be able to initialize the counter from
the records present so that neither path produces an ID that already exists.

## Acceptance

- A test that fails before the change: create a task, remove its file from the
  records root, create another task; the second ID is one higher than the
  removed one and the removed ID is never reused.
- The counter file is written atomically through `writeOwned` and survives a
  dry run unchanged.
- `just ci` passes.
