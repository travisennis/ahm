# Split validation.go into per-validator files

## Problem

`internal/ahm/validation.go` is a single file spanning six unrelated concerns:
task front matter, dependencies and cycles, bucket placement, ADRs,
generated-index freshness, and Markdown link walking (ADR 022 removed two of
the original eight). Nothing binds them together except the shared
`validationReport` type, so the file is the default landing place for any new
check and keeps growing.

The mitigating factor is what makes the split safe to do now: the findings-code
contract is a documented compatibility surface, so a mechanical move that
preserves codes and messages has a clear correctness test — the findings output
must not change at all.

Tasks 012 and 107 did the same split for the CLI god file and
`task_commands.go`; the precedent and the review conventions already exist.

## Relevant Files

- `internal/ahm/validation.go` — the file to split.
- `internal/ahm/validation_test.go` — findings coverage; may need splitting too
  (see task 030 for the precedent).
- `ARCHITECTURE.md` — module map, which must list the new files.
- `docs/references/workflow-spec.md` — findings-code contract.

## Fix Direction

Extract the shared `validationReport` type and its caches into their own file,
then move each validator into a file named for its concern. Keep the split
purely mechanical: no renamed functions, no changed finding codes, no changed
messages, no reordered findings. Behavior changes belong in separate tasks —
task 249 (metadata caching) and task 252 (cross-boundary record reuse) both
touch this file and should be sequenced deliberately against it.

## Acceptance Notes

- [ ] `validation.go` is split by validator; the shared report type and caches

- [ ] No finding code, message, or ordering changes; existing validation tests
      pass without modification.
- [ ] `ARCHITECTURE.md`'s module map lists every new file.
- [ ] No file in the split exceeds a size that reintroduces the same problem.
- [ ] `just ci` passes.
